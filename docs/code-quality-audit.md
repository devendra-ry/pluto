# Code and experience audit — 2 October 2026

This pass reviewed the app's feature layers and server boundaries, fixed reproducible defects, and updated the shared chat experience. It does not establish a numeric “100 times” improvement or guarantee the absence of every bug.

## Changes

| Area | Result |
| --- | --- |
| Request security | Exact JSON media-type validation rejects lookalikes. An invalid explicit Origin cannot use Referer as a fallback. |
| Generation jobs | Each claim receives a UUID token. Stale clients cannot complete a newer claim or persist its reply. Managed requests validate their token before provider work. |
| Reply persistence | A transaction locks the claimed job and its undeleted user-message anchor, saves the reply, and completes the job atomically. A deleted prompt cannot receive an orphan reply through this RPC. |
| Context limits | Plain-text attachment estimates account for file size. The server recalculates the output budget from prepared attachment bytes before contacting the provider. |
| Uploads | File admission distinguishes count, per-file, and total-size limits. Rejected files no longer consume the budget of later valid files. Removed uploaded draft files request cleanup. The composer supports file drops and keeps incompatible attachments visible. |
| Storage | New migrations match the default bucket's size cap to the application cap and remove object replacement through the old update policy. |
| Markdown and code | Math conversion preserves fenced, incomplete fenced, indented, and inline code. Preprocessor directives retain their characters. Code blocks have a dedicated exact-copy action. |
| Markdown responsiveness follow-up | Parsing, math, and completed-code highlighting run in a Web Worker with cancellation and a main-thread fallback. Completed documents reuse a bounded exact-source tree cache across remounts; custom renderers receive their own tree clone. A synthetic browser benchmark including React/DOM updates measured about 70% less UI blocking, with greater formatting latency; see `markdown-worker-performance.md`. |
| Conversation loading | Server hydration and client startup fetch the latest 50 messages with one lookahead row. Older pages load on demand and preserve the scroll anchor. Attachment links use stable authenticated URLs without eager signing; branch references retain access after parent deletion, and proxy responses vary by Cookie. Provider context reads only the five required fields. |
| Atomic branching | A PostgreSQL transaction copies the complete persisted prefix, including unloaded history and timestamp ties, remaps reply links, and preserves settings and reply metadata. Failed copying rolls back the entire branch. |
| Deletion and shared files | Thread deletion is atomic and undoable for 30 seconds. Durable cleanup jobs fence storage removal and final database deletion, retry failures, and protect shared references and other conversations' Undo windows. Positive ownership caching was removed so tombstones immediately revoke proxy access. |
| Message search and attachments | Search queries the conversation's persisted messages, displays the latest 20 matches with a limit notice, and loads older pages to jump/highlight a selected result. Closing search cancels a pending jump. Images expose loading/error/retry states and a larger accessible preview; other files provide named links. |
| Production tracing | Correlated request IDs and optional OpenTelemetry spans cover provider, database, storage and persistence stages. A loopback collector smoke confirmed HTTP/JSON export and sanitized exception metadata. See `observability.md`. |
| History and search | Thread history and search use an `(updated_at, id)` cursor instead of offsets, deduplicate results, retain successful rows on failure, and reuse the cursor on retry. Database indexes support cursor reads, title/message substring search, and exact attachment references. Server-prefetched conversation rows avoid a duplicate hydration query and remain scoped to their route. |
| Connection recovery | Messages reconcile after reconnect, returning online, and tab visibility changes; connection interruptions are visible. Closed channels are recreated rather than retained indefinitely. |
| Draft lifecycle | Text drafts persist per account and conversation, with home isolated from thread drafts, restore/discard feedback, bounded storage, expiry, and graceful storage failure. New Chat clears the home draft. Auth changes clear drafts, Markdown trees, and query cache; old content is hidden until server identity refresh completes. Draft epochs and fresh settings writers prevent stale setup and rollback callbacks from changing a new draft. |
| Performance measurement | `npm run analyze:chat-logs -- path/to/server.log` summarizes existing structured timing logs by model and stage with count, p50, p95, and stream outcomes. See `performance-log-analysis.md`; no production latency claim is inferred from synthetic tests. |
| Navigation | Conversations can be renamed. Mobile navigation supports Escape, focus trapping and restoration, and preserves prior body scroll styles. Empty/search states explain the next action. |
| Account access | Login displays callback and OAuth startup failures, with a recoverable action. |
| Accessibility and presentation | Shared starter cards, visible selected models, larger composer and upload controls, accessible upload progress, a keyboard-accessible instructions dialog, input limit feedback, and narrow-screen wrapping. Preference storage failures no longer crash the picker/sidebar. |
| Framework maintenance | Removed the deprecated Edge runtime declaration from the generated icon. Updated Next.js to 16.3.8 and compatible dependency patches; the dependency audit reports no vulnerabilities. |

## Database rollout and remaining verification

On October 2, 2026, the configured Supabase `dev.chat` project was brought up to the repository history through `202610020008`: twelve missing migrations were applied and confirmed, and no migrations remain pending. The claim-token and response-persistence changes require the database and application updates together; the fifth October migration adds thread pagination/search indexes, the sixth adds branching, Undo, cleanup jobs and storage policies, the seventh indexes database hot paths and closes legacy column-level UPDATE grants, and the eighth replaces quadratic branch reply mapping with relational joins. Restart/drain older server processes and refresh old browser clients: an already running server from before this change cannot be retroactively fenced. Legacy completion calls are intentionally safe no-ops, and direct thread deletes and message updates now use supported RPCs.

All migrations and all four SQL regression scripts pass in a temporary embedded PostgreSQL engine with local auth/storage schema stubs. The pending migration sequence also passed together with the SQL suites in rollback transactions against actual Supabase before deployment, with successful post-deployment verification. These checks include generation fencing, branching atomicity and dense reply mapping, Undo and cleanup claims, shared-file lifetimes, authenticated RLS/storage policies, attachment path ownership, account cleanup, and direct-update denial. Native PostgreSQL plans verified the new search and attachment indexes on temporary synthetic tables; see `database-performance.md`. Docker and `psql` are unavailable here, so the two-session concurrency suite still needs the CI/local Supabase run. CI provisions fresh Supabase and runs that suite; follow `supabase/migrations/README.md` and `docs/thread-lifecycle.md`.

Live Google OAuth, production Supabase policies/storage/realtime, and production Redis/provider behavior still need an authenticated staging smoke test. The automated suites provide local and mocked coverage for those boundaries.
